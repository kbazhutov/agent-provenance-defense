# Agent Provenance Defense

Исследовательский проект о защите LLM-агентов от indirect prompt injection.

## Исследовательский вопрос

Может ли проверка намерения пользователя, происхождения данных и аргументов вызова предотвратить изменение неправильных записей при наличии у агента формального права записи?

## Первый рабочий прототип

В прототипе агент читает документы и вызывает инструмент `update_record`. Baseline намеренно не проверяет происхождение документов и область исходной задачи. Поэтому вредоносный документ может расширить набор записей или изменить запрещённое поле.

Все данные синтетические. Перед каждым запуском создаётся независимый набор записей, поэтому сценарии воспроизводимы.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки не требуются.

```bash
python scripts/run_baseline.py
```

Скрипт печатает сводку и сохраняет:

- `results/baseline.csv`
- `results/baseline.json`

## Структура

- `research_plan.md` — постановка исследования и план экспериментов.
- `data/schema.sql` — схема локальной базы.
- `data/*.csv` — синтетические записи, документы и задания.
- `src/agent/baseline.py` — воспроизводимый baseline.
- `scripts/run_baseline.py` — запуск набора сценариев.
- `results/` — результаты запусков.

Следующий этап — добавить защитный брокер, который проверяет область задачи, происхождение данных и аргументы вызова, а затем сравнить его с baseline.
